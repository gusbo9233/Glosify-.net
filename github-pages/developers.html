01 · Azure

Azure services used

I used managed Azure services for hosting, data, AI features, file storage, speech, calls, and monitoring.

Azure App Service

Hosts the production ASP.NET Core app. GitHub Actions deploys a release package when changes are pushed.

Azure SQL Database

Stores users, vocabulary, quizzes, books, classrooms, assistant history, and credits. The app accesses it through Entity Framework Core.

Azure Blob Storage

Stores uploaded PDF books and cached text-to-speech audio outside the web app.

Azure AI Foundry

Powers the AI assistant, vocabulary generation, text extraction, speaking practice agents, and real-time subtitle translation.

Azure Speech

Provides speech tokens for the browser and creates spoken audio on the server.

Azure Communication Services

Creates calling identities and access tokens for live classroom calls.

Application Insights

Receives OpenTelemetry traces and metrics so I can see errors and follow requests in production.

Managed identity

Lets the deployed app authenticate to supported Azure services without keeping service passwords in the repository.

02 · .NET

.NET concepts used

ASP.NET Core MVC and Razor

Controllers handle web requests, view models prepare page data, and Razor views render the interface.

Dependency injection

Controllers receive the services they need through constructor injection. Service registration is kept in the application setup.

Entity Framework Core

The DbContext maps C# models to SQL tables. Migrations keep database schema changes versioned with the code.

Identity and authentication

ASP.NET Core Identity manages accounts. The website uses cookies, while API clients can use bearer tokens.

Interfaces and services

AI, storage, speech, quizzes, and classroom logic sit behind interfaces. This keeps controllers smaller and makes tests easier to write.

Middleware

The request pipeline applies security headers, rate limiting, authentication, authorization, routing, and error handling.

Options and configuration

Settings are read from configuration and mapped to typed options instead of being hard-coded into feature classes.

SignalR

A SignalR hub handles real-time classroom chat so new messages can reach connected users immediately.

03 · Chrome extension

How Live Subtitles connects

The Manifest V3 extension is a separate browser client for the same Glosify platform. It authorizes the user against Glosify, reads their learning-language choices and credit balance, and opens a short-lived WebSocket relay for each subtitle session.

1Chrome tabCaptures the tab’s audio while keeping it audible
2Glosify relayAuthenticates the account and enforces credit billing
3Azure AI FoundryTranslates the in-memory audio stream
4Subtitle overlayShows translated text on the current page
The browser never receives an Azure credential. Audio is not persisted, and original-language transcript storage is available only when the user explicitly enables it.

04 · Request flow

A typical app request

I keep the flow simple: the browser sends a request, a controller checks it, a service performs the feature logic, and EF Core or an Azure SDK handles the external resource.

1BrowserRazor page or JavaScript sends a request
2ControllerChecks input, user access, and response type
3ServiceRuns the feature logic
4EF Core or AzureReads data or calls a managed service

05 · Quality

Testing and deployment

The test project has 289 xUnit facts and theories. Tests use SQLite or in-memory replacements where possible, so most application logic can be checked without calling live Azure services. The Chrome extension also has focused Node-based tests for its audio, billing, relay, transcript, and interface logic.

GitHub Actions builds the .NET 10 solution in Release mode, creates the deployment package, signs in to Azure with OpenID Connect, and deploys to App Service.
