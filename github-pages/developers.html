01 · Overview

How the parts fit together

I built Glosify with ASP.NET Core MVC. Controllers handle requests, services contain most of the app logic, Entity Framework Core works with SQL Server, and Razor views create the pages. I use JavaScript for interactive features such as quizzes, the book reader, speaking practice, and classroom chat.

CLIENTRazor + JavaScriptPages and interactive features
HTTPMVC + API controllersInput checks and responses
DOMAINServicesQuizzes, books, classrooms, AI, and speech
PLATFORMEF Core + AzureSQL, files, AI services, and monitoring

02 · Features

Main parts of the app

Vocabulary & quizzes

Word sets, public collections, flashcards, typing practice, sentence work, quiz attempts, and custom templates.

Books

PDF upload, blob-backed storage, browser reading, text extraction, page-level translation, and vocabulary capture.

AI learning

The assistant can call tools, create vocabulary, read text from images, save chat context, and use the credit system.

Speaking

Speaking scenes use Azure AI Foundry, browser speech recognition, text-to-speech, and feedback after each turn.

Classrooms

Membership, invitations, assignments, shared content, live chat, and Azure Communication Services calling.

Accounts & API

The web app uses cookies, the mobile API uses bearer tokens, and sign-in also supports external providers.

04 · Code structure

Why I used services and interfaces

I put book storage, AI, speech, quiz sessions, and classroom features behind interfaces. This keeps the controllers smaller and makes it easier to test code without calling every external service.

BoundaryResponsibilityWhy it matters
ControllersHTTP, authorization, validation, status codesRequest code stays out of the services
ServicesFeature rules and coordinationI can test the logic without loading a page
Azure and database codeAzure, database, speech, storage, model accessExternal services are kept separate
View/browser layerPresentation and interaction statePages and browser interactions stay together
