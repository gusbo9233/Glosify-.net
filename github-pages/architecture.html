How the app works.

01 · Requests

What happens during a request

Program.cs is where I register services and configure authentication, authorization, rate limits, security headers, monitoring, and routes. Keeping this setup in one file makes it easier to see how the app starts.

1AuthenticateCookie or bearer token identifies the user
2ProtectRate limit, authorization, antiforgery, validation
3ExecuteThe controller calls a service
4ObserveThe app records useful metrics and traces

02 · Data

Where the app stores data

Azure SQL

I use EF Core and SQL Server for users, vocabulary, quizzes, classrooms, books, assistant chats, and AI credits.

Azure Blob Storage

Book files and cached audio are stored in Blob Storage. The database keeps their metadata.

Connection retries

Retry settings and longer startup timeouts help when Azure SQL is waking up or has a temporary error.

Database changes

EF Core migrations keep database changes in source control.

03 · AI and speech

How AI features are connected

I use separate services for model calls, tool calls, structured results, conversation state, and errors. Azure AI Foundry handles the generative AI features, while Azure Speech handles speech access and text-to-speech.

ServiceRole in GlosifyHow it is connected
Azure AI FoundryAssistant, vocabulary generation, extraction, speaking agentsService classes and managed identity
Azure SpeechBrowser speech recognition and synthesized tutor audioShort-lived tokens and server-side speech generation
Blob cacheReuse generated speech audioCached files avoid generating the same audio again
AI creditsTrack paid AI usageAccount balance and transaction records

04 · Realtime

Chat and calls

I use SignalR for classroom chat and live updates. Azure Communication Services provides the identities and tokens used for calls. These are separate because chat and calling have different jobs.

The app requires sign-in by default. I only mark public pages and static files as anonymous.

05 · Production

Basic reliability and security

Rate limiting

Login, AI, speech, translation, and classroom requests have separate rate limits.

Security headers

The app sets CSP, HSTS, referrer, frame, and content-type security headers.

Monitoring

OpenTelemetry sends traces and metrics to Azure Monitor when Application Insights is enabled.

Failure handling

Exception filters turn service errors into safer responses for the client.
