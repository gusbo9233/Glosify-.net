01 · Prerequisites

What a local environment needs.

.NET 10 SDK

The solution shares net10.0, nullable reference types, and implicit usings across app and tests.

SQL Server

A valid DefaultConnection is required at startup. Use SQL Server or a compatible local development instance.

Azure access, optional

Cloud-backed AI, speech, blobs, and communication features require configured resources. Core local work can focus on non-cloud slices.

Secret storage

Keep credentials outside tracked JSON. The web project declares a user-secrets ID for developer-only values.

02 · Start locally

Restore, configure, run.

From the repository root, restore packages and provide the required SQL connection through user secrets before starting the web project.

dotnet restore dotnet user-secrets set "ConnectionStrings:DefaultConnection" "YOUR_SQL_CONNECTION" --project Glosify dotnet run --project Glosify
Do not commit connection strings, client secrets, subscription identifiers, or model credentials. Use user secrets locally and host configuration in Azure.

03 · Configuration

Configuration follows ASP.NET Core conventions.

JSON establishes non-secret defaults; user secrets and environment variables override values per environment. Nested keys use double underscores in host settings.

04 · Test strategy

Fast service tests plus targeted integration coverage.

The xUnit project covers domain services, controllers, authorization, HTML navigation, API validation, SignalR clients, data behavior, Azure adapters, AI tool orchestration, and speaking scenarios. In-memory and SQLite providers keep most database tests isolated; live cloud smoke tests are opt-in by configuration.

05 · Delivery

One workflow from commit to production.

Pushes to master trigger the application delivery workflow: restore and build on .NET 10, publish a release artifact, authenticate to Azure with OpenID Connect, and deploy that artifact to Azure App Service.
