01 · Before you start

What you need

.NET 10 SDK

The app and tests use net10.0. A local tool manifest pins the matching EF Core command-line tool.

Container runtime

Local development uses the SQL Server container in docker-compose.dev.yml instead of the Azure database.

Azure access, optional

AI, speech, file storage, and calling need Azure resources. The core app and default CI checks do not need paid cloud credentials.

Secret storage

I keep local credentials in .NET user secrets instead of committing them to JSON files.

02 · Local setup

Start the app

From the repository root, restore the pinned tool, start SQL Server, save the local connection string, create the schema, and run the web project.

dotnet tool restore docker compose -f docker-compose.dev.yml up -d dotnet user-secrets set "ConnectionStrings:DefaultConnection" "YOUR_LOCAL_SQL_CONNECTION" --project Glosify ./scripts/dev-db-reset.sh dotnet run --project Glosify
The reset script drops only the disposable local development database and recreates it through the checked-in EF migration.

03 · Settings

Where settings come from

The JSON file contains normal defaults. I use user secrets locally and environment variables in Azure for values that should not be committed. Nested environment-variable keys use double underscores.

04 · Tests

Running the tests

I use xUnit for application behavior, dependency-free Node tests for browser code, and Playwright for complete user journeys. Live Foundry tests run only when they are explicitly enabled.

dotnet test Glosify.Tests/Glosify.Tests.csproj npm test --prefix Glosify.ClientTests npm test --prefix Glosify.LiveSubtitles.Extension

05 · Deployment

How the app is deployed

A pull request runs the same deterministic checks used for master. After merge, GitHub Actions signs in to Azure with OpenID Connect, applies the reviewed migration bundle, and deploys the web package to App Service.

1Validate databaseApply migrations to an empty SQL Server and check the model
2TestRun .NET, JavaScript, and Chromium journeys
3PackagePublish the app and build the EF migration bundle
4DeployRun migrations first, then deploy to Azure App Service
