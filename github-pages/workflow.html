01 · Before you start

What you need

.NET 10 SDK

The app and tests both use net10.0, nullable reference types, and implicit usings.

SQL Server

The app needs a valid DefaultConnection when it starts.

Azure access, optional

AI, speech, file storage, and calling need Azure resources. Other features can still be worked on locally.

Secret storage

I keep local credentials in .NET user secrets instead of committing them to JSON files.

02 · Local setup

Start the app

From the repository root, restore the packages, add a SQL connection with user secrets, and run the web project.

dotnet restore dotnet user-secrets set "ConnectionStrings:DefaultConnection" "YOUR_SQL_CONNECTION" --project Glosify dotnet run --project Glosify
Do not commit connection strings or API credentials. Use user secrets locally and Azure settings in production.

03 · Settings

Where settings come from

The JSON file contains normal defaults. I use user secrets locally and environment variables in Azure for values that should not be committed. Nested environment-variable keys use double underscores.

04 · Tests

Running the tests

I use xUnit for services, controllers, authorization, navigation, API validation, SignalR, data access, Azure adapters, AI tools, and speaking features. Most database tests use in-memory data or SQLite. Live cloud tests only run when they are configured.

dotnet test dotnet test --configuration Release dotnet build --configuration Release

05 · Deployment

How the app is deployed

A push to master starts GitHub Actions. The workflow builds the .NET 10 project, creates a release package, signs in to Azure with OpenID Connect, and deploys the package to App Service.

1CheckoutGitHub Actions reads the repository
2BuildThe solution is built in Release mode
3PublishThe workflow creates the deployment package
4DeployThe package is sent to Azure App Service
